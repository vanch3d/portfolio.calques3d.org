Lead frontend role on HiveMQ Edge, the open-source MQTT broker for industrial IoT — owning the canvas topology visualiser, device creation wizard, and OpenAPI type-safety pipeline from early prototype to production release.

HiveMQ Edge is an open-source MQTT broker designed for industrial IoT — bridging legacy protocols (OPC-UA, Modbus, Siemens S7) to MQTT and enabling edge-based data processing before cloud transmission. As Lead Frontend Engineer, I owned the UI layer from early prototype through production release, making architectural decisions that shaped both the product and the team's engineering practices.

The canvas-based topology visualiser (React Flow) was the product's primary differentiator — a live, interactive graph of MQTT adapter connections, data flows, and transformation rules. Designing for industrial operators meant prioritising legibility at a glance over expressiveness: the canvas had to communicate system state unambiguously to engineers who might be 200ms away from a production incident.

The OpenAPI type-safety pipeline eliminated an entire class of runtime errors by generating TypeScript types from the backend's OpenAPI spec at build time. This made the API contract a compile-time constraint rather than a convention, and caught integration bugs that would previously have shipped to production.
