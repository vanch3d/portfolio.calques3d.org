# i18n Rules — next-intl

All user-facing strings must be externalised to `messages/en.json`. No hardcoded
UI copy anywhere in components or pages. See ADR 006 for decisions and rationale.

---

## The hard rule

**Every string visible to the user must come from `messages/en.json` via `getTranslations()` or `useTranslations()`.**

This includes: headings, labels, button text, aria-labels, link text, empty states,
error messages, pluralised counts. It excludes: data-driven content from JSON/MDX
(position titles, project names, publication titles — these are content, not UI copy).

---

## API by context

| Context | Function | Import |
|---|---|---|
| Async Server Component (page) | `getTranslations(namespace)` | `next-intl/server` |
| Client Component | `useTranslations(namespace)` | `next-intl` |
| Sub-component (sync, CT-compatible) | receives `labels` prop — see pattern below | — |

---

## Sub-component pattern (CT-compatible)

Sub-components must remain synchronous to work in Cypress Component Testing.
Pages resolve translations and pass them as a typed `labels` prop.

```tsx
// 1. Define the Labels interface in the component file
export interface ProjectCardLabels {
  fundedBy: (funder: string) => string; // ICU interpolation wrapped in a function
  ongoing: string;
}

// 2. Accept labels as a prop
export function ProjectCard({ project, labels }: { project: ResearchProject; labels: ProjectCardLabels }) {
  const endLabel = project.period.end ?? labels.ongoing;
  return <p>{labels.fundedBy(project.funding)}</p>;
}

// 3. Resolve in the parent page
const t = await getTranslations("ResearchPage");
const cardLabels: ProjectCardLabels = {
  fundedBy: (funder) => t("funded_by", { funder }),
  ongoing: t("ongoing"),
};
<ProjectCard project={project} labels={cardLabels} />

// 4. CT test passes explicit strings — independent of the translation file
cy.mount(<ProjectCard project={base} labels={{ fundedBy: (f) => `Funded by ${f}`, ongoing: "ongoing" }} />)
```

---

## Namespace conventions

- Top-level key = page or domain name: `ResearchPage`, `Publications`, `CVPage`, `HomePage`
- Message keys: `snake_case`
- ICU interpolation for dynamic values: `"funded_by": "Funded by {funder}"`
- ICU plurals for counts: `"positions_count": "{count, plural, =0 {...} =1 {...} other {...}}"`
- Do not share keys across namespaces — if two components need the same string, duplicate it

---

## Adding a new string

1. Add to `messages/en.json` under the appropriate namespace
2. If it's a sub-component string, update its `*Labels` interface
3. Resolve in the parent page's `getTranslations()` call and add to the `labels` object
4. TypeScript will catch missing keys in the `labels` object — fix before committing

---

## Adding a new locale (when needed)

1. Create `messages/<locale>.json` with all keys from `en.json` translated
2. Update `src/i18n/request.ts` to accept the new locale
3. Add `[locale]` routing segment to `app/` (see Next.js i18n routing docs)
4. Update `src/types/i18n.d.ts` if needed
